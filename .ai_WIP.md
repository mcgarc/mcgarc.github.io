# Hadley: sandboxed agentic AI workflow for research

This note was written by a human, without AI intervention. Hadley currently
operates with placeholder name "kit."

Hadley is a tool that manages sandboxed AI agents to operate on your computer.
The goal is to harness the benefits of agentic LLMs, while reducing the inherit
risk of granting access to an entire file system. It also encourages a workflow
that allows prolonged autonomous work by the agent, with oversight from the
human provided by a plan, which is constructed and explicitly approved before
work begins.

Using Hadley, each agent exists in a sandbox (essentially a lightweight virtual
machine) which runs on the host computer. The container restricts the agents
access to the wider filesystem and the internet. This protects local files, and
mitigates prompt injection. The agent can reach the relevant third-party
servers for inference, and, for example, other select services such as for
downloading Python packages.

Inside the container there is a project folder. This is a human-readable
library of markdown files which serves as the agent's long term memory. It is
an interface to the agent that goes beyond the chat window. The human can pass
files to the agent, and access simulations and reports generated by the agent.

The project folder also contains a read-only library, managed by a separate
"hub" agent. The library contains both papers and notes on these papers
(written by the human or an agent). This is synchronised with an external
Zotero library. This mitigates against hallucinated citations. Agents can
request papers be added to the library, which must be performed by the user. A
daily arXiv digest is performed automatically, and papers of interest to the
user are highlighted.

Agents operate under a set of directives which are designed to protect the
user's personal information, and encourage human oversight. Longer tasks (those
that take over ~15 minutes) must have a plan, which is typitcally written by
the agent and edited by the human. Often the agent will clarify the details of
the plan by asking questions. Work does not begin until the plan is explicitly
approved. Plans are stored in the project library.

Progress between sessions is stored in long term memory by means of a
constantly updated status file in the project library, and handovers which are
generated before exiting. Handing over for a new session is a helpful way to
manage the agent's context window (short-term memory).

Software running on the host system saves version history for the containers
using git. The history is stored outside the container, so that the agent
cannot edit it.

Unsurprisingly, the codebase is entirely AI generated. A maintainer agent is
used to build the code and tests are run when new software is deployed to the
host. All changes are human-reviewed. Nonetheless, this software is used at the
user's own risk.
